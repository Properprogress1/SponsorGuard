# Privacy data map and review assumptions

This is an engineering record for review by a data protection adviser. It records assumptions to validate for the deployment, customer arrangements and applicable processing. SponsorGuard tracks your records. It does not provide immigration advice or guarantee compliance.

One person may have multiple independent records. Select each file or record that belongs to the person when reviewing a request. Check unstructured fields and uploads for references stored against somebody else. Previously downloaded exports, third-party copies and records in backups require separate procedures. Confirm provider backup lifetimes and arrange for erased records to be kept beyond use in backups and removed from any restored production system. [ICO right to erasure guidance](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/right-to-erasure/)

## Lawful-basis assumptions to review

- The subscribing organisation is expected to be the controller for its workforce and personnel records. SponsorGuard is expected to act on its documented instructions as processor for those records, subject to the contractual arrangements. Review whether SponsorGuard acts as controller for its own account, security, billing and service administration purposes. Check partner arrangements, subprocessors, UK-region settings and international transfer safeguards. [ICO controller and processor guidance](https://ico.org.uk/for-organisations/advice-for-small-organisations/getting-started-with-gdpr/data-protection-principles-definitions-and-key-terms/)
- The adviser should identify the actual provision behind any Article 6 legal-obligation basis for specific right-to-work or sponsorship records. Consider whether contract necessity applies to account administration, and whether a documented legitimate-interests assessment is appropriate for fraud prevention, security and evidence integrity. Check separate rules for special-category or criminal-offence data if present, including any additional statutory conditions. [ICO lawful-basis guide](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/lawful-basis/a-guide-to-lawful-basis/)
- Agree purpose-specific retention, any overriding reason to keep a record, and the applied safeguards before enabling automatic purge. The app starts with no retention periods and does not decide if a request should be granted. Review timelines, identity verification, third-party disclosure and deletion from backups and external recipients. [ICO storage limitation guidance](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-protection-principles/a-guide-to-the-data-protection-principles/storage-limitation/), [ICO right to erasure guidance](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/right-to-erasure/)

## Running privacy actions

Native owners and admins with verified MFA can open **Privacy**, inspect activity and request exports, including for retained records after a downgrade. A native owner can approve manual erasure, add retention versions or place a hold. JSON and PDF include the original ready files up to a combined 25 MiB. If a file is unavailable or the total exceeds the limit, the request fails. Use individual vault downloads when preparing a larger response. Verify the requester and any third-party redactions before sending an export.

Enter an approved source, effective date and calendar-day period for each relevant person type, then record each person's authorised retention start date. The latest rule effective on the current London date applies to eligible records. Leave the period blank in a new version to pause that category, omit the start date to exclude the record, or apply a hold to prevent scheduled and manual erasure.

The checked-in Vercel schedule invokes `GET /api/cron/privacy` daily in the 10:00 UTC hour. Use the hourly cadence described in the deployment guide for commercial deployments. The scheduler calls the route with `Authorization: Bearer <CRON_SECRET>`. Configure the Supabase service role and cron secret before approving erasure. The database cuts off new access and records the file queue atomically, then the worker removes bytes. Failed file removals remain pending and are retried. During that interval, an already issued signed URL may still work until it expires or the file is removed. The page shows outstanding file removals. Finish these before rollback. Audit pack invalidation, reversals after restores, and deletion of retained provider logs or external files belong in the incident and rights-response runbooks.
